# 项目工作空间管理（`matter-workspace`）

## 功能定位

为多客户、多项目执业建立相互隔离的工作空间，管理项目的新建、列示、切换、关闭和退出活动项目。其核心作用是让其他法律 Skill 只读取当前项目的事实、偏好和成果，避免客户信息交叉污染。

## 适用场景

- 私人执业团队同时处理多个客户或多个独立事项；
- 新建项目并记录客户、相对方、项目类型、保密等级和特殊偏好；
- 在不同项目之间切换当前上下文；
- 关闭项目并保留可追溯的历史记录；
- 临时退出项目上下文，仅使用团队级通用配置。

## 不适用场景

- 单一客户的公司法务场景且团队已选择只使用团队级上下文；
- 代替正式利益冲突检索、立项审批或信息隔离墙；
- 代替档案保管、数据留存和销毁制度；
- 未经明确授权读取其他项目文件；
- 把“关闭项目”理解为删除项目资料。

## 使用前准备

- 项目 slug，使用小写字母和连字符；
- 客户、相对方和其他关键参与方；
- 项目类型、关键事实及主要负责人；
- 保密等级：普通、加强或 clean-team；
- 相对团队默认规则的项目特定偏离；
- 关联项目以及是否允许跨项目比较。

## 预期输出

- 新项目的 `matter.md`、历史记录和工作笔记；
- 当前项目列表、状态、开启日期和活动标记；
- 当前活动项目的切换确认；
- 关闭项目的归档记录，不删除原资料；
- 可供其他 Skill 读取的项目级上下文和保密边界。

## 调用方式

本地 Codex：

```text
$matter-workspace new acme-investment-2026
$matter-workspace list
$matter-workspace switch acme-investment-2026
$matter-workspace close acme-investment-2026
$matter-workspace none
```

原始 Claude 插件命令为 `/corporate-legal:matter-workspace`，其子命令与上述逻辑相同。

## 工作流程

1. 确认团队是否启用了多项目工作空间；
2. 新建项目时检查 slug 是否重复，并收集项目和保密信息；
3. 写入项目说明、历史记录和工作笔记，但不自动切换；
4. 切换项目时更新单一活动项目标记，并向使用者展示项目摘要；
5. 关闭项目时追加关闭记录并移动至归档区；
6. 默认禁止读取其他项目；即便允许跨项目上下文，也必须由用户明确提出比较请求。

## 律师确认事项

- 客户、相对方和关联方信息是否足以支持正式冲突检索；
- 项目保密等级和可访问人员是否正确；
- 是否存在 clean-team、内幕信息或其他信息墙要求；
- 项目特定偏离是否获得客户或内部批准；
- 关闭、归档、保留和删除是否符合本所档案制度。

## 兼容性与本地化

原 Skill 把数据写入 `~/.claude/.../matters/` 并通过 Claude 配置记录活动项目。本地 Codex 需要另行确定团队共享目录、权限模型、备份和活动项目状态文件。工作空间隔离只是 Agent 上下文控制，不能替代律所正式冲突系统、文档管理系统和访问控制。
