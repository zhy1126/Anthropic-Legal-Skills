# AI 批量审阅工具交接（`ai-tool-handoff`）

## 功能定位

在 Luminance、Kira 或类似批量审阅平台已经投入使用时，本 Skill 负责组织文件交接、设定提取字段、按团队信任等级复核平台输出，并把机械提取结果转化为可供律师判断的工作底稿。它管理的是“交接和 QA”，不是直接运行外部平台。

## 适用场景

- 同类合同数量较大，通常超过 50 份；
- 目标是寻找变更控制、转让限制、排他、最惠国、终止权或自动续期等标准条款；
- 文件格式较统一，团队已经购买并熟悉外部审阅平台；
- 批量提取结果需要抽样复核、全量复核或进一步判断是否真的触发交易后果。

原 Skill 建议先考虑 `tabular-review`。如果本地 Codex 能处理文件规模和字段结构，本地表格化审阅通常更直接，也更容易控制数据去向。

## 不适用场景

- 数量不大、条款高度定制或谈判痕迹明显的文件；
- 需要同时理解主协议、补充协议和 side letter 相互作用的任务；
- 问题本质是“该条款对本交易意味着什么”，而不只是“是否存在该条款”；
- 团队没有配置外部工具、操作人员或审阅信任等级。

## 使用前准备

- 文件清单、资料室位置及拟交接的合同类别；
- 需要提取的条款类型和重要性门槛；
- 外部平台名称、项目空间及实际上传负责人；
- 团队批准的信任等级：直接使用、按比例抽查或对命中文件全面复核；
- 交易结构，以及判断条款是否触发所需的关键事实。

## 预期输出

- 外部平台批量加载请求或操作说明；
- 文件数量、提取目标、交付时间和过滤口径；
- QA 抽样范围、错误率及扩大复核建议；
- 条款命中数量、实际触发数量和重大事项数量；
- 应进入尽调问题清单或交割清单的后续事项。

## 调用方式

本地 Codex：

```text
$ai-tool-handoff
请把这批客户合同交给现有批量审阅平台提取变更控制和转让限制，并按团队批准的抽查比例复核结果。
```

原始 Claude 插件命令为 `/corporate-legal:ai-tool-handoff`。

## 工作流程

1. 判断是否应先使用本地 `tabular-review`，以及本批文件是否适合外部平台；
2. 确认文件范围、提取字段、重要性门槛和实际上传负责人；
3. 形成加载请求并由有权限的人员在外部平台执行；
4. 按既定信任等级抽样或复核平台输出，记录错误率；
5. 对命中条款增加交易结构判断，区分“存在条款”和“实际触发”；
6. 将重大事项交接给尽调、交易团队摘要或交割清单流程。

## 律师确认事项

- 外部平台的数据处理条款和客户授权是否允许上传；
- 抽样比例是否足以支持本项目，发现错误后是否需要扩大样本；
- 变更控制、转让限制等条款是否因本次交易结构而实际触发；
- 哪些事项超过重要性门槛，是否需要取得同意或调整交易文件；
- QA 摘要及底层文件的保密和特权分发范围。

## 兼容性与本地化

原 Skill 依赖 Claude 配置文件中的外部工具、信任等级和项目路径。本仓库尚未把这些路径改写为 Codex 配置，也未替团队选择任何外部平台。正式使用前应完成工具连接、数据合规和项目权限配置；中国法项目中的条款效力及交易触发判断由经办律师确认。
