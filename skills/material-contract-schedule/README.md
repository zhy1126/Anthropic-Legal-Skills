# 重大合同披露清单（`material-contract-schedule`）

## 功能定位

依据交易文件中“重大合同”定义，将尽调阶段已审阅的合同逐项匹配定义门槛，并按照披露清单的批准格式形成初稿。交易文件定义控制纳入范围，团队的一般尽调门槛不能替代该定义。

## 适用场景

- 为股权收购、资产收购或其他交易准备重大合同披露清单；
- 将合同尽调结果转化为交易文件附件或披露日程；
- 逐项记录合同满足的定义分项、缺失字段和纳入依据；
- 单独建立内部第三方同意跟踪表并交接至交割清单；
- 对临界合同、口头安排、side letter 和拟终止合同提示律师判断。

## 不适用场景

- 在没有取得当前交易文件定义时使用通用“重大合同”口径；
- 自行修改、扩大或缩小交易文件中的重大合同定义；
- 代替尽调阶段读取底层合同；
- 代替律师起草陈述保证条款或决定披露策略；
- 把内部同意状态、特权分析或工作注释直接放入对外交付版本。

## 使用前准备

- 最新交易文件及完整“重大合同”定义；
- 披露清单的编号、格式和其他清单样例；
- 合同尽调结果、表格化审阅结果或合同台账；
- 合同名称、相对方、日期、期限、金额、VDR 位置等字段；
- 交易结构、行业监管和政府合同等特殊转让规则；
- 当前第三方同意需求和状态。

## 预期输出

- 按定义分项组织的重大合同披露清单初稿；
- 每份合同满足的定义分项及纳入/排除依据；
- 缺失信息、临界案例和待律师决定事项；
- 与其他披露清单、陈述保证和 VDR 文件的交叉核对结果；
- 单独的内部同意跟踪表及交割清单交接项。

## 调用方式

本地 Codex：

```text
$material-contract-schedule
请读取交易文件中的重大合同定义，将现有合同尽调结果逐项匹配定义，并按批准的披露清单格式生成初稿。
```

原始 Claude 插件命令为 `/corporate-legal:material-contract-schedule`。

## 工作流程

1. 从当前交易文件提取重大合同定义和披露清单格式；
2. 识别定义中的金额、期限、合同类型、排他、转让及其他分项；
3. 将每份已审合同逐项匹配定义，满足任一分项即纳入候选；
4. 收集相对方、标题、日期、期限、金额、定义分项和 VDR 引用；
5. 对临界、缺失、口头或拟终止安排作醒目标记，不自行猜测；
6. 按交易文件格式编排，并单独生成内部同意跟踪层；
7. 完成完整性、过度披露、跨清单一致性和文件引用核对。

## 律师确认事项

- 使用的是否为当前版本交易文件中的完整定义；
- 每项纳入或排除结论是否符合具体定义分项；
- 临界合同、side letter、口头安排和关联交易如何处理；
- 行业监管、政府合同、知识产权等特殊同意或转让规则；
- 对外交付版本是否已删除内部分析、同意状态和特权注释；
- 清单与其他陈述保证、披露清单和底层 VDR 是否一致。

## 兼容性与本地化

原 Skill 假设美国式购买协议和披露清单结构，并从 Claude 项目目录读取尽调结果。中国法交易需要结合合同约定、资产或股权交易结构、国资、外资、行业许可及政府采购等规则调整，但仍应坚持“交易文件定义控制纳入范围”的基本方法。
