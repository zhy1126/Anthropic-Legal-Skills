# 尽调问题提取（`diligence-issue-extraction`）

## 功能定位

按照团队批准的尽调类别、重要性门槛和问题备忘录格式，盘点资料室、审阅文件、提取问题、标注出处并形成分类问题清单。它负责从大量材料中找出需要律师判断和交易团队处理的事项。

## 适用场景

- 对 VDR、共享文件夹或指定文件开展法律尽调；
- 按公司治理、重大合同、知识产权、劳动和争议等类别提取问题；
- 识别材料缺口、冲突文件和需要补充问询的事实；
- 将第三方同意、公司批准、监管申报、解除或付款安排交接给后续流程；
- 对大量同类合同先进行批量交接，再处理复杂和高判断性文件。

## 不适用场景

- 在没有明确审阅范围、交易立场或重要性门槛时进行无边界审阅；
- 代替律师决定处于门槛边缘的问题是否重大；
- 代替交易文件谈判、陈述保证或赔偿条款起草；
- 用模型记忆补足未检索到的法条、案例或材料内容；
- 把逐文件、逐字段批量提取任务误当成问题识别；此类任务应使用 `tabular-review`。

## 使用前准备

- 项目立场、交易结构、法域、审阅范围和保密等级；
- 资料室路径、文件索引或本地文件；
- 团队批准的尽调清单、类别和重要性阈值；
- 历史问题备忘录或批准的 finding 格式；
- 项目特定门槛、交易时间表和交易负责人；
- 可用的法律检索来源，以及未检索到结果时的升级规则。

## 预期输出

- VDR 文件盘点、类别映射、覆盖率和材料缺口；
- 按类别及严重程度排序的问题清单；
- 每项问题的文件路径、页码或 Bates 等可追溯出处；
- 事实、交易影响、建议行动和待确认事项；
- 向交易团队摘要、重大合同披露清单和交割清单的结构化交接。

## 调用方式

本地 Codex：

```text
$diligence-issue-extraction
请按本项目批准的重要性标准审阅指定资料室，先盘点覆盖范围，再输出有文件出处的问题清单和材料缺口。
```

原始 Claude 插件命令为 `/corporate-legal:diligence-issue-extraction`。

## 工作流程

1. 加载团队门槛、问题格式和项目特定上下文；
2. 盘点 VDR，映射尽调类别并列出没有响应材料的请求项；
3. 按批准门槛过滤文件，避免无差别审阅；
4. 对每份文件识别适用问题并保留原文、位置和来源；
5. 对引用的法条、案例和监管材料标明检索来源；检索覆盖不足时停止并请律师选择下一来源；
6. 按团队格式和严重程度形成分类问题清单；
7. 将所有可能需要交割前行动的事项完整交给 `closing-checklist`。

## 律师确认事项

- 审阅范围、重要性门槛和抽样方法是否适合本交易；
- 事实提取和文件引用是否准确、完整且可复核；
- 风险评级、交易影响和建议行动是否成立；
- 法律依据是否来自当前有效的权威来源，是否存在境外法或专业边界；
- 继受责任、合同同意、公司批准和监管事项是否需要升级；
- 问题清单的保密、特权标记和分发范围是否妥当。

## 兼容性与本地化

原 Skill 使用 Claude 的 VDR 连接、项目文件夹和美国并购问题示例。本地 Codex 可以读取本地或已连接材料，但必须重新配置项目隔离和来源标记。中国法项目应重新建立公司、合同、知识产权、劳动、数据、反垄断、外资、国资、行业监管等类别及门槛，并由经办律师确认法律结论。
