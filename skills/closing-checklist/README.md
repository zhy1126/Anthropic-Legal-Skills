# 交割清单管理（`closing-checklist`）

## 功能定位

从交易文件、尽调发现和项目更新中维护动态交割清单，记录条件先决、交割文件、责任人、期限、完成证据、阻塞状态和关键路径。它回答的是“距离交割还缺什么、什么最可能影响交割日”。

## 适用场景

- 从签署版或接近定稿的交易文件初始化交割清单；
- 把尽调发现、重大合同同意事项和交易团队摘要中的交割行动纳入清单；
- 更新责任人、进度、证明文件、预计完成时间和阻塞因素；
- 形成交割状态报告、关键路径和距目标交割日天数；
- 识别需要豁免、补救、加急或升级决策的事项。

## 不适用场景

- 代替经办人员实际取得同意、办理申报或签署交割文件；
- 在没有读取交易文件的情况下自行决定哪些事项构成交割条件；
- 仅凭“已完成”文字而不核查签署件、批复、回执或其他关闭证据；
- 代替律师出具最终“全部交割条件已满足”结论。

## 使用前准备

- 签署版或最新交易文件及条件先决、交割交付物、交割前承诺条款；
- 目标签署日、交割日和交易结构；
- 尽调问题清单、重大合同同意事项和最新项目摘要；
- 每项责任人、预计完成时间、依赖关系及完成证明；
- 监管审批、第三方同意和重大不利变化等事项的最新法律核验。

## 预期输出

- 可持续更新的结构化交割清单；
- 按风险区分的阻塞事项、在轨事项和已完成事项；
- 每项来源条款、责任人、期限、状态和证据记录；
- 关键路径、到期风险和目标交割日倒计时；
- 需要律师、交易负责人或管理层决定的升级事项。

## 调用方式

本地 Codex：

```text
$closing-checklist
请根据交易文件和最新项目状态更新交割清单，列出真正阻塞交割的事项、关键路径和关闭证据缺口。
```

原始 Claude 插件命令为 `/corporate-legal:closing-checklist`。

## 工作流程

1. 从交易文件逐项提取条件先决、交割交付物和交割前期限；
2. 为每项记录来源条款、责任人、截止日、阻塞属性和预计耗时；
3. 接收尽调、披露清单和团队摘要中的交割行动，并按交易对方和行动类型去重合并；
4. 根据项目更新补充进度、依赖、条件、通知期限和证明文件；
5. 比较剩余时间与预计完成时间，识别关键路径及到期风险；
6. 输出状态报告，并对未关闭事项提出补救、升级或豁免问题。

## 律师确认事项

- 每项是否确属交易文件规定的交割条件或交付物；
- 监管审批、等待期、同意机制及重大不利变化判断是否基于最新规则和具体条款；
- 完成证据是否充分，是否存在附条件同意、遗漏签署或未生效文件；
- 未完成事项能否豁免、由谁豁免、是否需要 side letter 或例外清单；
- 在出具“可以交割”或交割备忘录前，律师是否完成逐项确认。

## 兼容性与本地化

原 Skill 将清单写入 Claude 的交易目录，并大量引用美国并购审批和公司法示例。本地 Codex 使用时应改为团队批准的项目目录和清单格式。中国项目的反垄断、外商投资、国资、行业许可、数据及公司审批事项必须重新识别，不能沿用美国法时间假设。
