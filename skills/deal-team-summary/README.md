# 交易团队摘要（`deal-team-summary`）

## 功能定位

把已经形成的尽调发现压缩成适合不同受众阅读的交易简报。它不重新进行尽调，而是回答：目前最重要的问题是什么、相较上次有什么变化、谁需要在什么时间作出决定。

## 适用场景

- 向董事会、管理层或交易发起人汇报最重大问题；
- 向交易负责人汇报全部红色、黄色事项、审阅覆盖率和待决策事项；
- 为工作团队整理完整发现、材料缺口、责任分工和未来 72 小时安排；
- 周期性更新中突出新增、升级、降级和已关闭的问题。

## 不适用场景

- 代替底层文件审阅或尽调问题提取；
- 在底层发现没有经过律师确认时自行改变重要性评级；
- 替管理层选择价格调整、赔偿、交易结构或退出方案；
- 自动向业务团队或交易相对方分发可能受保密或特权保护的材料。

## 使用前准备

- 最新、完整且有来源的尽调问题清单；
- 项目基本信息、交易阶段、时间表和交易负责人；
- 本次简报受众：董事会/管理层、交易负责人或工作团队；
- 团队批准的重要性等级、简报格式和分发范围；
- 上次简报或基准版本，用于比较变化。

## 预期输出

- 管理层版：3–5 项重大问题、交易影响和待决策事项；
- 交易负责人版：全部高优先级问题、覆盖率、材料缺口和下一步；
- 工作团队版：完整发现、状态、责任人和交接事项；
- 与上次简报相比的新增、关闭及评级变化；
- 可能进入交割清单的行动事项。

## 调用方式

本地 Codex：

```text
$deal-team-summary
请根据最新尽调问题清单，分别形成管理层摘要和交易负责人工作摘要，重点说明变化和待决策事项。
```

原始 Claude 插件命令为 `/corporate-legal:deal-team-summary`。

## 工作流程

1. 读取团队简报偏好、项目上下文和最新尽调发现；
2. 确认受众层级及其需要和不需要看到的信息；
3. 提取重大事项、交易影响、责任人和决策期限；
4. 如有上次版本，优先呈现新增、关闭和评级变化；
5. 根据受众控制细节：管理层只看结论，工作团队保留完整发现；
6. 将形成交割行动的事项交接给 `closing-checklist`。

## 律师确认事项

- 底层发现、来源和重要性评级是否准确；
- 摘要是否遗漏会影响价格、结构、审批或交割的事项；
- “待决策”描述是否清楚区分法律建议、商业判断和会计税务判断；
- 分发对象是否处于适当的保密或特权范围；
- 摘要与底层尽调备忘录、交易文件和最新事实是否一致。

## 兼容性与本地化

原 Skill 从 Claude 的项目目录和团队配置中读取简报节奏及格式。本地 Codex 需要明确指定问题清单、受众和历史版本。中国项目应按团队实际风险等级、保密制度和交易审批流程调整简报，不应直接沿用美国式红黄绿含义或特权表述。
