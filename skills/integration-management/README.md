# 并购后整合管理（`integration-management`）

## 功能定位

管理并购交割后的法律整合工作流，包括分阶段工作计划、交易文件后续义务、第三方同意、合同转让、主体整合、知识产权登记和周期性状态报告。它是法律工作流的项目管理层，不负责 IT、HR、财务等业务整合本身。

## 适用场景

- 从交易文件、交割清单或现有待办初始化 Day 1/30/90/180 工作计划；
- 跟踪交易文件约定的交割后义务、存续期、托管释放和关键日期；
- 导入合同清单并按同意、变更控制和自动转让机制分层；
- 更新同意取得、谈判、拒绝、转让完成和阻塞状态；
- 形成法律整合周报、管理层摘要及 CSV/表格导出。

## 不适用场景

- 代替 HR、IT、财务或业务团队管理其整合项目；
- 代为起草、发送第三方同意函或办理合同更名、转让和变更登记；
- 对同意被拒或逾期事项直接作出违约、赔偿或解除结论；
- 计算或跟踪 earn-out 业绩；Skill 只记录由财务负责的关键日期；
- 在报告阶段重新审阅全部底层合同；报告读取的是已经维护的台账状态。

## 使用前准备

- 交易代号、标的、交割日、交易负责人和外部律师；
- 完整交易文件或至少交易摘要、交割清单和现有整合待办；
- 必须取得和希望取得的第三方同意清单；
- 合同库、重大合同披露清单或合同管理系统导出；
- 交割后承诺、陈述保证存续、托管释放和 earn-out 日期；
- 责任人、截止日、依赖关系、当前状态和证明材料。

## 预期输出

- Day 1、30、90、180 分阶段法律整合工作计划；
- 必须同意和期望同意的独立跟踪表；
- 按 Tier 1–4 分类的合同转让及变更控制台账；
- 逾期事项、近期任务、阻塞因素和待决策问题；
- 状态报告以及安全转义后的 CSV 或 Markdown 导出。

## 调用方式

本地 Codex：

```text
$integration-management --init
请根据交易文件和交割清单建立交割后法律整合计划，提取硬性期限，并明确哪些工作由法律负责、哪些只是法律支持。
```

常用模式还包括 `--contracts`、`--report`、`--update` 和 `--export`。原始 Claude 插件命令为 `/corporate-legal:integration-management`。

## 工作流程

1. 加载交易上下文和未关闭的交割后事项；
2. 从交易文件或现有材料提取同意、后续义务和关键日期；
3. 建立分阶段工作计划，区分 `legal-owns` 和 `legal-supports`；
4. 导入合同清单，读取转让和变更控制条款并分配 Tier；
5. 对合同沉默、管辖法默认规则和变更控制触发进行律师复核；
6. 持续更新状态，形成周报、风险升级和导出结果。

## 律师确认事项

- 交易文件中的硬性期限和 Required Consents 清单是否完整；
- 陈述保证存续期、托管、价款调整和 earn-out 日期是否准确；
- 合同转让机制、变更控制触发及合同沉默时的适用法规则；
- 被拒同意、逾期或未完成义务是否触发交易文件责任；
- 主体合并、注销、知识产权转让、员工和数据事项的专业分工；
- 状态报告的保密、特权和收件人范围。

## 兼容性与本地化

原 Skill 的标准工作计划和文件路径源自美国并购实践及 Claude 配置。中国项目应重新设计市场监管、税务、外汇、国资、行业许可、劳动用工、数据迁移、知识产权登记及印章证照等整合任务。所有期限和法律结论以交易文件、适用法和经办专业人员确认结果为准。
