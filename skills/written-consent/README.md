# 董事会书面决议（`written-consent`）

## 功能定位

从团队批准的历史书面决议或已配置的决议库中寻找最接近的先例，按既有格式起草董事会或委员会一致书面决议初稿，并附签署人清单、利益冲突提示、适用法核验和流转前检查事项。

## 适用场景

- 日常高管任免、股权激励、银行授权、常规合同批准和年度授权；
- 公司内部往来、注册地址或注册代理变更等有直接先例的事项；
- 多项相关决议需要在一份书面决议中处理；
- 需要匹配既有 recital、resolution、授权和签字页格式；
- 重大一次性事项的律师审阅初稿，但不是未经审查的签署版本。

## 不适用场景

- 没有任何历史先例或格式资料，却要求直接生成可签署的通用决议；
- M&A、融资、解散、资本结构变化等重大事项要求当天立即签署，且尚未经过外部律师审查；
- 代替律师判断某事项是否需要董事会批准或能否采用书面决议；
- 代替董事义务、利益冲突、表决门槛和公司文件分析；
- 代为发送签署、追踪签字或归档正式公司记录。

## 使用前准备

- 最近的同类历史书面决议或 3–5 份批准的种子文件；
- 公司名称、主体类型、注册地和公司文件；
- 拟批准事项、有效日期、金额、相对方和支持文件；
- 董事会或委员会完整成员名单；
- 董事利益冲突、回避或披露情况；
- 适用法对一致同意、通知、电子签名和副本签署的当前要求。

## 预期输出

- 严格匹配先例格式的书面决议草稿；
- 清晰具体的批准事项、实施授权和附件引用；
- 必需签署人、利益冲突和适用法提示清单；
- 流转前律师复核问题；
- 在签署前应删除的“供律师审阅”提示。

## 调用方式

本地 Codex：

```text
$written-consent
请使用已批准的历史先例，为本次银行签字授权起草董事会一致书面决议初稿，并附签署人和流转前检查清单。
```

原始 Claude 插件命令为 `/corporate-legal:written-consent`。

## 工作流程

1. 读取团队决议格式、董事会组成、公司注册地和历史先例位置；
2. 如无先例，停止并要求用户提供历史文件或明确接受通用草稿；
3. 识别批准事项、有效日期、签署主体、支持文件和利益冲突；
4. 将事项分类为日常行动或重大一次性行动；
5. 对重大事项提示外部律师审阅；如又要求当天签署，则在律师路径确认前停止；
6. 搜索最接近的先例并保持 recital、决议、授权及签署格式一致；
7. 核验注册地法律、章程和议事文件中的书面决议规则；
8. 输出草稿、签署清单和流转前检查表。

## 律师确认事项

- 该事项是否需要董事会或委员会批准，书面决议是否为适当形式；
- 批准范围、金额、协议名称、附件和授权人员是否具体准确；
- 董事利益冲突、披露、回避和受托义务如何处理；
- 签署门槛、通知要求、电子签名和副本签署是否有效；
- 重大交易是否已经得到外部律师审查；
- 在流转签署前是否删除所有占位符和律师复核提示。

## 兼容性与本地化

原 Skill 以美国公司董事会一致书面同意为核心，并从 Claude 的决议库和团队配置读取格式。中国公司、红筹主体和其他法域在决议主体、表决门槛、签字盖章、备案和公司文件效力方面差异明显，必须按具体主体和适用法重新核验。
