# 批量表格化审阅（`tabular-review`）

## 功能定位

对一批文件重复提取同一组数据点，形成“一份文件一行、一个字段一列”的审阅表，并为每个单元格保留原文和精确位置。它把人工复核路径结构化，不把模型结果包装成已经确认的法律结论。

## 适用场景

- 批量比较合同中的变更控制、转让、期限、责任限制等字段；
- 对租赁、供应商、客户或知识产权合同建立统一审阅网格；
- 需要 Excel、Google Sheets、CSV 和 Markdown 输出；
- 需要区分“条款不存在”“条款不清楚”和“需要律师判断”；
- 后续拟把结构化结果交给重大合同披露清单或尽调流程。

## 不适用场景

- 目标是从大量材料中寻找少数重大问题；应使用 `diligence-issue-extraction`；
- 没有统一字段，或不同文件需要完全不同的法律问题；
- 希望用模型置信分数代替底层原文和人工复核；
- 需要把无法定位的内容补写成“原文”；
- 要求自动跳过无法读取的文件。

## 使用前准备

- 待审文件夹、Drive/VDR 路径或明确文件清单；
- 需要提取的列、固定选项和字段类型；
- 交易或项目上下文、重要性门槛和法域；
- 输出格式：Excel、Google Sheets 或 CSV；
- 期望的抽样数量和律师复核比例；
- 如有，提供现成 `.review-schema.yaml` 或 M&A 模板。

## 预期输出

- 经确认的字段 schema 和 3–5 份文件样本结果；
- 每份文件一行的标准化数据表；
- 每个值的状态、连续原文、条款位置和复核标志；
- CSV 主表、来源表和 Markdown 预览；
- Excel/Sheets 中的隐藏来源列、备注及 Verified 列；
- `not_present`、`unclear` 和 `needs_review` 的复核工作量统计。

## 调用方式

本地 Codex：

```text
$tabular-review
请审阅该文件夹中的合同，先和我确认字段 schema，再抽取变更控制、转让限制、期限和责任上限；每个值必须带原文和位置。
```

也可使用 `--schema`、`--docs`、`--output`、`--sample` 或 `--template ma-diligence`。原始 Claude 插件命令为 `/corporate-legal:tabular-review`。

## 工作流程

1. 确认文件范围、字段 schema 和输出位置；
2. 为每一列指定 `verbatim`、`classify`、`date`、`duration`、`currency`、`number` 或 `free` 类型；
3. 先审阅 3–5 份样本，修正含义不清或选项不足的字段；
4. 对每份文件逐列提取值、状态、连续原文和精确位置；
5. 逐列规范化格式，复核异常值和分类不一致；
6. 随机抽查原文是否与底层文件逐字一致；发现一个错引即扩大复核范围；
7. 输出工作簿、CSV、来源表和人工验证统计。

## 律师确认事项

- schema 是否准确表达审阅问题，选项是否覆盖实际条款；
- 每项引用是否可在指定位置逐字找到；
- `unclear` 和 `needs_review` 是否得到人工处理；
- 适用法或交易结构是否改变对条款的解释；
- 在结果进入披露、备忘录或交易文件前，哪些单元格已经人工验证；
- 表格是否安全处理公式注入、换行和外部输入。

## 兼容性与本地化

原 Skill 假设能够并行处理文件，并可能连接 Excel、Google Sheets 或 VDR。具体连接和输出能力取决于本地 Codex 环境。该方法本身与法域无关，但列定义、分类选项和法律解释必须针对中国法或项目适用法重新设计。
